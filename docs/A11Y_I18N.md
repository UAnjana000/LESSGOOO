# Web accessibility and internationalisation (EN / HI / MR)

Scope: the React PWA in `web/`, covering the visitor kiosk and phone screens, the smart-display signage page and the archivist workspace. Source requirements: spec §5.5 (Indian-language access) and §5.6 (accessibility), plus WCAG 2.2 Level A and AA.

Last verified 2026-09-27 on Windows (Node, Vitest 5 with jsdom, axe-core 4.13).

## Internationalisation

- **Coverage:** every interface string on the visitor screens (`pages/`, `components/`) and in the archivist workspace (`staff/`) comes from `STRINGS` in `web/src/i18n.ts`. That is **490 keys per language** (177 visitor keys plus 313 staff keys in `web/src/i18n.staff.ts`, merged into `STRINGS`), or **1,470 strings** across EN, HI and MR.
- **Staff workspace:** previously English-only, with `lang="en"` forced. It now follows the session language and has a labelled language picker on the login page and in the header. Option lists show translated labels while sending the same API values: item type, document class, collection, access level, rights permissions and date certainty.
- **Tests that fail on a gap** (`i18n.test.ts`):
  - Every language has exactly the same keys, and no string is empty.
  - Every `{placeholder}` used in English appears in HI and MR.
  - HI and MR strings contain Devanagari, which catches strings left in English.
  - Every collection, item type and map-node label the API can send has a key.
  - Every backend derivative label maps to a translated string.
  - Every staff key exists in every language.
  - A scan of `pages/*.tsx`, `components/*.tsx` and `staff/*.tsx` flags hard-coded English JSX text, `aria-label`, `alt`, `placeholder` or `title`.
  - The translation-review flag (below) cannot say "native reviewed" without a reviewer name and an ISO date.
- **`lang` attributes:** `<html lang>` follows the UI language on every screen, including staff; `a11y.test.tsx` asserts this for each route in all three languages. Archive text in another script is marked with its own `lang` via `textLang()`. Staff textareas and translations carry the content's language, and language options carry `lang` for their own name.

### Native-speaker review is still pending

All Hindi and Marathi interface copy was written by the build team's AI agents, not by native speakers. **No native-speaker review has been done.** This is flagged in two places:

- In code: `TRANSLATION_REVIEW` in `web/src/i18n.ts` sets `hi` and `mr` to `agent_drafted_pending_native_review`, with `reviewer: null`.
- In this document.

To sign a language off, a native speaker reads every string in `i18n.ts` and `i18n.staff.ts`. Then set that language's `status: "native_reviewed"` with the reviewer's name and the date; the test enforces both fields.

Terms worth a reviewer's particular attention:

- "Sarvam", "OCR", "SHA-256" and "USD" are left in Latin script.
- Archival terms: "संरक्षण मूल प्रति" (preservation master), "उद्धरण सत्यापित" / "उद्धरण पडताळलेले" (quote-verified), "प्रतिलेख" (transcript).
- Marathi uses "साहित्य" for "item".

Also in place (verified by reading the code, and partly by the tests above):

- `:focus-visible` rings on all controls and a focus-ring colour held to 3:1 (contrast test).

A scan for the Web Interface Guidelines anti-patterns (zoom disabled, `transition: all`, `outline: none`, `onPaste` blocking, `...` instead of `…`) found **0 matches** in `web/src` and `index.html`.

### Fixed in this pass

- Staff workspace was English-only with `lang="en"` forced. All strings are now translated, and the page follows the chosen language.
- Staff navigation links were about 44 px tall; they are now 48 px minimum (`.staff-top nav a`).
- The staff skip link, accessible table names, image `alt` text, `title` and `window.confirm` prompts were hard-coded English; they now come from i18n.
- The axe and touch-target suites previously ran in English, with one Hindi case; they now cover all three languages and the staff workspace.

### Known gaps (not verified)

- **No manual screen-reader test** (NVDA, TalkBack or VoiceOver) and no keyboard-only walkthrough by a person.
- **No test on the Lenovo tablet kiosk or the smart display.** Touch-target sizes come from computed CSS minimums in jsdom, not measured rendered boxes.
- **Contrast is checked on design tokens**, not rendered pixels. jsdom has no layout, so axe's `color-contrast` rule is disabled there. The Playwright suite (`web/e2e/`, owned by the browser-test agent, using `@axe-core/playwright`) is where rendered contrast belongs.
- Values the API sends are shown as sent, in English: status and enum codes, server error messages, publication "problems", and dashboard count keys. Staff dates are ISO strings rather than `Intl.DateTimeFormat`.
- Code tokens (the bootstrap command, hashes) are not marked `translate="no"`.
- Native-speaker review of HI and MR is pending (see above).
- The key-parity tests were not red-green checked in this pass by deleting a key. They are structural, key-by-key comparisons that existed before this work.
